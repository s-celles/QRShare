# Development

QRShare uses [Bun](https://bun.sh) for dependencies, tests and builds. The
optional [just](https://github.com/casey/just) recipes wrap the same commands.

## Quick Start

```bash
# Install dependencies
bun install

# Start development server
bun run dev

# Run tests
bun test

# Type check
bun run typecheck

# Production build (dist/)
bun run build

# Serve dist/ locally
bun run serve

# Package the main script and styles into qrshare.html
# (workers and WebAssembly files must stay next to it)
bun run package
```

## Web App Manifest and Store Assets

`manifest.webmanifest` (copied to `dist/` by `scripts/build.ts`) describes the
installed app. Besides the name, colours, icons and share target, it declares:

- `id: "/QRShare/"` — the install identity. Browsers resolve `id` against the
  *origin* of `start_url`, not against the manifest URL, so `"./"` would give
  `https://s-celles.github.io/` and make installed copies look like a different
  app. `/QRShare/` equals the start URL that browsers used as the identity before
  `id` existed, so existing installs are kept.
- `scope`, `lang`, `dir`, `orientation: "any"`, `categories` and
  `display_override` (`standalone`, then `minimal-ui`).
- `launch_handler` with `client_mode: ["navigate-new"]`: a shortcut, a share or a
  start opens a new window. `navigate-existing` would reload a window in the
  middle of a transfer, and `focus-existing` would need the app to read
  `window.launchQueue` (it does not), so shared content would be lost.
- Icons with an explicit `purpose`: `any` for the SVG and the 192/512 px PNGs, and
  separate `maskable` 192/512 px PNGs (a full-bleed background with the artwork
  inside the safe zone, the centred circle of 80 % of the icon size). The maskable
  192 px icon is also the `apple-touch-icon`.
- `shortcuts` to `#/scan`, `#/create`, `#/send/qr` and `#/receive/qr`, with 96 px
  icons in `assets/shortcuts/` (a test checks that each URL is a real route).
- `screenshots`: two `wide` (1280 × 800) and two `narrow` (540 × 1200) captures of
  the built app, with labels, in `assets/screenshots/`.

The PNGs are committed and regenerated by two scripts, which drive a headless
Chromium through its command line and the DevTools protocol (no automation
package). They use `$CHROME`, or else the newest `chromium_headless_shell-*` of the
Playwright browser cache (`~/.cache/ms-playwright`, filled by
`bunx playwright install chromium-headless-shell`):

```bash
# Maskable and shortcut icons, from assets/icon.svg and inline SVG glyphs
bun run icons

# Store screenshots of the built app (served from dist/ on a local port)
bun run build && bun run screenshots
```

`tests/pwa-manifest.test.ts` checks the manifest fields, that every image it lists
exists with the declared pixel size (read from the PNG header), that maskable
icons have opaque corners, and that the build copies the images and the service
worker precaches only files that exist. The single-file `qrshare.html` has no
manifest, so none of this applies to it.

Possible follow-ups, not declared because the app does not handle them yet:
`file_handlers` (would need `window.launchQueue` to receive the opened files),
`protocol_handlers`, `edge_side_panel` (the camera views are not designed for a
narrow side panel) and `iarc_rating_id` (needs an IARC certificate).

## Documentation

The pages in `docs/` are Markdown files. They are bundled into the app and shown
in-app under `#/docs`; the list of pages lives in `src/ui/docs.ts`. To add a page,
create the Markdown file, then register it there with its title. Links between
pages use the relative file name (for example `en-user-guide.md`, or
`en-user-guide.md#section-title` for a section), which works both on GitHub and in
the app.

A page has its own address in the app, used by the README links:

- `#/docs?page=<slug>` — a page, in the interface language when translated
- `&lang=fr` — force a translation (`en` or `fr`)
- `&section=<anchor>` — scroll to a heading; anchors follow GitHub's rules
  (`Exchanging Files with Other Web Apps` → `exchanging-files-with-other-web-apps`)

## Requirements

[`docs/requirements.md`](requirements.md) is the EARS specification of QRShare
(also shown in the app and linked from the About window). Every requirement has an
ID such as `REQ-QRX-004`, a MoSCoW priority and the release that introduced it.
Cite IDs in code comments and test names; `tests/requirements.test.ts` checks that
each cited ID is defined, that IDs are unique and that every requirement follows
an EARS pattern. When behaviour changes, update the requirement in the same commit.

## Releasing a New Version

1. **Bump the version** in `package.json` and `src/version.ts`
2. **Update `CHANGELOG.md`**: move entries from `[Unreleased]` into a new `[X.Y.Z] - YYYY-MM-DD` section, and replace *Unreleased* by `X.Y.Z` in the **Since** column of `docs/requirements.md`
3. **Run checks**:
   ```bash
   bun test
   bun run build
   ```
4. **Commit** the version bump:
   ```bash
   git add package.json src/version.ts CHANGELOG.md
   git commit -m "chore(release): X.Y.Z"
   ```
5. **Tag** the release:
   ```bash
   git tag -a vX.Y.Z -m "QRShare X.Y.Z"
   ```
6. **Push** commit and tag:
   ```bash
   git push && git push --tags
   ```
7. **(Optional) Create a GitHub Release** from the tag:
   ```bash
   gh release create vX.Y.Z --title "vX.Y.Z" --notes-from-tag
   ```

Pushing to `main` runs the CI workflow, which tests, builds and deploys the app to
GitHub Pages.
